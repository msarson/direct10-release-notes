In development
24 Fixed 11 Improved

What you should know about 2026.4.002

2026.4.002 gives MoverBiz a new look with a choice of themes, including a Dark Mode, and dates that follow your Windows region. In the Trip Planner the jobs list works again, and drivers are now chosen from a list for each company instead of typed as a number. It also fixes a range of MoverBiz problems in the Load Board, reports, standard letters and the tariff interface.

2026.4.002 also makes Print Paychecks explain exactly what to correct when payroll hours are posted to a month that is already closed in the General Ledger, instead of reporting that there were no records to process. Commercial Records invoices now print each customer’s own city, state and ZIP code, and custom-format invoices no longer show a “BIND has not been called” error. Users marked as inactive can no longer sign in. It also stops Payroll and MoverBiz from overwriting whatever you had copied to the clipboard, and corrects a problem saving the first data set on a new installation.

All changes in 2026.4.002

Payroll

  • Print Paychecks said there were no records to process when hours were in a closed month Fixed

    Applies to: anyone calculating paychecks (Transactions > Print Paychecks).

    Each line of payroll hours carries its own Posting Month/Year. If a line was posted to a month that is already closed in the General Ledger, Calculate Paychecks could stop with “There were no records to process”, even though the hours were plainly there in the Standard Database. It now tells you which employee has hours in a closed month, which month that is, the month the General Ledger is closed through, and to correct the Posting Month/Year in Edit Hours Database. To find the lines involved, use Print Detail on the Database Summary screen and check the “Post” column.

  • Print Paychecks replaced whatever you had copied to the clipboard Fixed

    Applies to: anyone using Transactions > Print Paychecks.

    Viewing calculated paychecks copied a technical query to the Windows clipboard, replacing anything you had copied. It no longer touches the clipboard.

  • E-File W2 Forms menu item removed Improved

    Applies to: Payroll users.

    Reports > Yearly Reports > W2 Forms > E-File W2 Forms only ever showed a “coming soon” message, so it has been removed. Printing W2 forms is unchanged.

Dispatch

  • A new look for MoverBiz, with a choice of themes Improved

    Applies to: everyone using MoverBiz.

    MoverBiz has a refreshed, more modern look. You can now choose a theme on the Home tab under Appearance > Theme: Microsoft 365 Blue, Silver, White or Black, a Dark Mode, Office 2013 White, Office 2010 Blue or Silver, or your Windows colors. Your choice is remembered for your Windows user. The ribbon now sits in the window’s title bar, and text, grids and disabled items stay readable in every theme. Images, Letters and Job Listings opened from Direct10 keep the standard blue look. The ribbon no longer has an Exit button; close MoverBiz with the window’s close button, as before.

  • MoverBiz buttons use the same icons as Direct10 Improved

    Applies to: everyone using MoverBiz.

    OK, Cancel, Save, Add, Help and the other standard buttons now show the same icons you see in the rest of Direct10.

  • Dates and times in MoverBiz follow your Windows region Improved

    Applies to: MoverBiz users whose Windows region is not United States, for example the United Kingdom.

    Date and time boxes always showed month/day/year and a 12-hour clock. They now use the date and time format set in Windows, so a UK PC shows day/month/year and a 24-hour clock. US PCs look the same as before. Searches and filters by date give the same results whatever the region.

  • Assign Driver: choose the driver from a list instead of typing a number Improved

    Applies to: anyone assigning drivers in the MoverBiz Trip Planner.

    Assign Driver used to ask for a driver number, and applied that one number to every job on the trip, even jobs in another company where the number belongs to someone else. Driver numbers belong to each company, so Assign Driver now shows a list for each company on the trip, holding that company’s active commission agents by number and name. Choosing a driver for one company fills in the other companies where the same person has a number. OK assigns the drivers to the trip’s jobs and closes. Opening Assign Driver again shows the drivers the jobs already have.

  • Edit Trip shows the trip’s driver by name Improved

    Applies to: anyone editing trips in the MoverBiz Trip Planner.

    The Driver box on Edit Trip was a number you typed. It now shows the driver the trip’s jobs have, by number and name, or tells you when the jobs have no driver or different drivers. To change it, use the Assign Driver button beside it.

  • Trip Planner is clearer about what you can do Improved

    Applies to: anyone using the MoverBiz Trip Planner.

    The list at the top is now headed “Jobs not on a trip”: drag a job from it onto the trip below to add it. Assign Driver, Export Trip to CSV and Print Trip Planner are unavailable until the trip has at least one job.

  • Required fields and entry mistakes are easier to see Improved

    Applies to: everyone entering information in MoverBiz.

    Required fields are marked, and when something can’t be saved MoverBiz now lists what needs correcting and highlights the fields involved, instead of failing quietly. Several messages with misspellings or the wrong wording have been corrected.

  • New IBS Support Portal button and help links Improved

    Applies to: everyone using MoverBiz.

    On the Support tab, the Bomgar Portal button is replaced by IBS Support Portal, which opens the Splashtop SOS download page for remote support sessions. Help links now open the new online help.

  • Security improvements in MoverBiz Improved

    Applies to: everyone using MoverBiz.

    MoverBiz is now stricter about the files, folders and links it will open, handles names and text typed into searches more safely, and keeps technical connection details out of its messages.

  • Trip Planner showed no jobs to plan Fixed

    Applies to: anyone using the MoverBiz Trip Planner.

    The list of jobs available for a trip was always empty, so jobs could not be added to trips. It now lists the active jobs that are not on a trip, narrowed by the filter on the left.

  • Opening a shipment from MoverBiz used the wrong data set Fixed

    Applies to: sites with more than one data set.

    A shipment opened from MoverBiz opened in the default data set instead of the one you were working in. It now opens in your current data set.

  • An edited standard letter could not be saved Fixed

    Applies to: anyone editing standard letters in MoverBiz.

    Saving changes to a standard letter always failed. It now saves.

  • Load Board assignments: available resources list was empty Fixed

    Applies to: anyone assigning crews and equipment on the MoverBiz Load Board.

    The list of available resources never filled in. It now shows the resources available for the work ticket’s dates. The check for double-booked resources also now takes the type of resource into account, so an employee and a vehicle that share a number are no longer reported as a conflict.

  • Load Board: date error stayed after the dates were reset Fixed

    Applies to: anyone choosing From and To dates on the MoverBiz Load Board, for example in View > Reports > Selected Work Tickets.

    When the From date was after the To date, both dates went back to their previous values, but the From date kept its error mark until you clicked Set Dates again. The mark now clears with the reset.

  • Work Type Colors added duplicate rows Fixed

    Applies to: anyone setting work type colors in MoverBiz.

    Work types that do not belong to a company got a new duplicate color row each time the Work Type Colors window was opened and saved. They now keep their existing row.

  • Cancelling a job clone showed an error Fixed

    Applies to: anyone cloning jobs in MoverBiz.

    Cancelling a job clone, or a clone that failed, showed an error message and left the window open. It now closes cleanly.

  • Cancelling the File Extensions or File Actions windows reloaded the list Fixed

    Applies to: anyone maintaining file extensions or file actions in MoverBiz.

    Pressing Cancel still reloaded the list behind it, losing your place. Cancel now leaves the list as it was.

  • MoverBiz reports said there were no matching records when they could not load Fixed

    Applies to: anyone running MoverBiz reports.

    If a report could not read its data, for example because of a connection or permission problem, it showed an empty result as if nothing matched. It now says the report could not be loaded. Reports also load more reliably while you change their options.

  • An apostrophe in a report filter stopped the report Fixed

    Applies to: anyone filtering MoverBiz reports and boards by text.

    Filtering by a value containing an apostrophe, such as a name like O’Brien, gave an error. These values now filter correctly.

  • Tariff interface: the Interstate option imported intrastate jobs Fixed

    Applies to: anyone importing jobs through the tariff interface (QuickMove).

    Choosing Interstate looked up and imported intrastate jobs. It now imports interstate jobs.

  • Tariff interface: sign-in and start-up errors Fixed

    Applies to: anyone using the tariff interface (QuickMove).

    Signing in with the “own credentials” option failed. The configuration and import windows could also stop with an error when a lookup list was empty, a licence key or default settings were missing, or a transfer number was blank. These now work, or explain what is missing.

  • XML export left out military details Fixed

    Applies to: anyone exporting military shipments to XML.

    When one of a military shipment’s number fields was blank, the export left out all of its military details. They are now exported, with the blank field left empty.

  • Standard letter names with an apostrophe were not checked for duplicates Fixed

    Applies to: anyone adding or renaming standard letters in MoverBiz.

    When a letter’s name contained an apostrophe, such as O’Brien Welcome, MoverBiz could not tell whether a letter with that name already existed, so a second letter could be saved under the same name. The check now works for any name.

  • Filters failed for a coordinator, dispatcher or work type with an apostrophe Fixed

    Applies to: anyone filtering the Load Board, Job Listings or MoverBiz reports.

    Choosing a move coordinator, dispatcher or work type whose ID or name contains an apostrophe stopped the list or report from loading. These now filter correctly.

  • Warehouse report could leave out jobs that arrived with a time of day Fixed

    Applies to: anyone running the MoverBiz warehouse reports (New Jobs Received and Jobs in Warehouse).

    The reports only counted jobs whose warehouse arrival was recorded at midnight. A job whose arrival included a time of day, as some imported jobs do, was missed on the day it arrived. Both reports now count the whole day, the same as the warehouse reports in Direct10.

  • The Locate box stopped at an apostrophe, * or % Fixed

    Applies to: anyone using a Locate box above a MoverBiz list.

    Typing an apostrophe, an asterisk or a percent sign into a Locate box stopped it finding anything. These characters are now matched as typed. Locating a number also now works whatever your Windows region.

  • Opening MoverBiz replaced whatever you had copied to the clipboard Fixed

    Applies to: anyone opening MoverBiz screens from Direct10.

    Opening a MoverBiz screen copied its technical start-up details to the Windows clipboard, replacing anything you had copied. It no longer touches the clipboard.

Commercial Records Storage

  • Invoices printed the same city, state and ZIP code for every customer Fixed

    Applies to: anyone printing Commercial Records storage invoices, work orders or pull lists, with the standard or a custom invoice format.

    The customer’s name and street address printed correctly, but the city, state and ZIP code line could show another customer’s details, so every invoice in a batch ended with the same city. Each invoice, work order and pull list now prints the customer’s own city, state and ZIP code. If you mailed invoices printed with an earlier version, check the city line and reprint any that are wrong.

  • Custom-format invoices showed a “BIND has not been called” error Fixed

    Applies to: anyone printing Commercial Records invoices with the Custom invoice format.

    Print All Invoices or Print One Invoice could show a “View Open Error: BIND has not been called” message, and the invoices could then include more than the ones you chose. The error no longer appears, and each run prints only the invoices you selected for your company.

  • Saving a printed invoice as a PDF overwrote the previous one Fixed

    Applies to: anyone saving Commercial Records invoices as PDF files from Print Invoices.

    When you saved the preview from Print All Invoices or Print One Invoice, the suggested file name was always the same, and each save replaced the last one. The name now shows “All” for Print All or the invoice number for Print One, followed by the date and time, so each save is kept. Invoices sent by email are not affected.

General

  • New data set could not be saved when no data sets existed yet Fixed

    Applies to: anyone adding the first data set in the Database Install, Clone and Upgrade Wizard (SQLInstallAndUpgrade), for example on a new installation or a new server.

    When no data sets existed yet, the Data Set ID on the new data set form was left blank and could not be entered, so pressing OK refused to save because the ID was missing. The first data set is now given ID 1 automatically. Adding a second data set in the same session also now gets the next ID, instead of reusing the one just created. Systems that already have data sets are not affected.

  • Inactive users can no longer sign in Improved

    Applies to: everyone signing in to Direct10.

    A user whose account is marked inactive could still sign in. Inactive users are now refused at sign-in, with the same message as an unknown user ID. To let someone back in, mark their user as active again.
